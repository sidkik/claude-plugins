# Native MAIN observation

Claude setup selects the plugin's observed MAIN agent and enables the experimental observer feature for future sessions. Setup preserves the user's model, effort, tools, permissions, authentication, project instructions, and unrelated settings.

The managed observer covers MAIN only; worker delegation remains available without observer fanout. At native observer startup, a narrowly matched `SubagentStart` hook supplies the exact MAIN transcript identity and an ordered public-record baseline, excluding internal metadata and reasoning. The hook reads a snapshot up to 32 MiB and includes up to 256 KiB of public records at whole-record boundaries; exceeded limits and omitted public content are explicit. Claude may replace larger hook context with a preview and its native persisted-output path; the observer reads that exact normalized output before treating the baseline as loaded. Native output follows Claude’s retention; the plugin creates no independent archive. The observer consumes this history, then reconciles incremental digests; targeted reads resolve specific missing evidence. Incomplete or truncated history remains unknown and cannot prove an earlier prerequisite was skipped. This historical baseline does not repair native first-turn timing.

An existing custom `agent` setting conflicts with automatic MAIN observation. Preserve it and report the exact setup gap; the human chooses whether to replace that custom default. Never weaken permissions or silently start an unobserved session.

Distinguish configuration from runtime proof. Doctor's `ready` covers installation and configuration; its separate `observer` result reports runtime limitations and leaves activity `not-checked`. Claude Code 2.1.285 has a verified initialization defect: the native observer misses the first interactive MAIN turn. Report `known-missing` even when setup is correct. Setup repair or restarting that version cannot establish first-turn coverage; continue independent SDLC work. Other versions remain `unverified`, including newer releases, until evidence covers the first real interactive MAIN turn.

A matching native `observer-ref` or a delivered report with the exact native observer origin proves observer activity as of that record. Before either record, report `starting`; the compact footer uses the stricter `observer-ref` projection. Missing setup, a custom-agent conflict, or an unsupported Claude version is `unavailable`. Preserve the first-turn limitation alongside these activity states: a later record does not prove earlier coverage, and a historical record is not a live heartbeat. Observation cannot attach to an existing session, so corrected setup takes effect after a fresh session starts.

When the user requests observation visibility, start the packaged live view for one explicit MAIN transcript and expected session ID. Return its capability URL and stop handle; do not make the user copy files or configure a server. The view shows validated native launches, delivered findings, subsequent visible MAIN actions, and a raised → assessed → acted → verified trace. It separates recorded input batches from delivered findings, and shows evidence-backed corrections, attributed usefulness, disputes/redundancy, possible misses and measured disruption. Unknown dimensions remain unknown. Treat no evidence as unknown, and state that recorded launch or activity does not prove every earlier turn was observed.

Automatic tracking uses compact finding metadata in native deliveries and private outcome annotations in the observer's own transcript. The managed observer instructions define the protocol; MAIN can respond normally. The viewer validates exact native identities and cited MAIN records after delivery, reconstructing the trace on restart. Acknowledgment alone never verifies correction. Verification is an observer-attributed judgment backed by actual tool evidence, not independent proof; conversational corrections remain assessed/unverified. Misses are opportunistic findings, not an exhaustive recall audit. Token usage is deduplicated recorded observer usage where available; monetary cost is unknown. Partial/unavailable transcript sources qualify every total. No additional per-turn observer invocation, repository log or separate session archive is created. Native transcript annotations follow Claude retention. Optional manual assessments remain memory-only and never inflate automatic verified counts.

Start or reuse the view for the current MAIN with this procedure, the single source that `session-start` points to:

1. Take MAIN's native `sessionId` and absolute transcript path from the same native identity. Resolve the installed `sdlc-process` plugin root; its CLI is `node <installed-plugin-root>/scripts/observer-live.mjs`.
2. Reuse a retained viewer only when a bounded GET of its `state` endpoint succeeds, shows this MAIN's `sessionId`, reports an owner incarnation bound to the current MAIN, and does not report `coverage: unavailable`. A legacy unowned or stale viewer is never reused. When current ownership cannot be established, start a verified owned view or report the gap, and leave unrelated processes running.
3. Otherwise run `serve --owner-main --transcript <absolute-main-transcript> --session <actual-main-id>` through the agent's supported background-process handle, with no arbitrary total deadline: a foreground polling timeout must not become a two-hour viewer lifetime. If the host cannot provide a durable handle, state that concrete limitation rather than claiming persistent monitoring. When owner discovery fails, report the runtime's concrete gap and leave the view unstarted; owner discovery is currently Linux/WSL.
4. Verify the launch JSON and `state`: the session ID equals MAIN's and the owner incarnation is present. Return the browser URL and stop handle to the requester and keep them private to this conversation.

Completion: a verified owned view for the current MAIN, or the exact gap.

- `serve --owner-main --transcript ABSOLUTE.jsonl --session SESSION_ID` prints the browser URL, assessment URL, stop URL and owner identity. The runtime resolves MAIN from its own process ancestry, requires exactly one `--session-id` or `--resume` match for that UUID, records the process ID and start ticks, and closes the view when that MAIN incarnation ends, is reused or is no longer live. The user supplies no PID or path. A manual `serve` with neither ownership mode is unowned; the explicit paired `--owner-pid PID --owner-start-ticks TICKS` flags make it owned. Native launches always use `--owner-main`.
- `assess --url ASSESSMENT_URL --report UUID --outcome corrected|continued|disputed|unresolved --assessor ID --role ROLE --rationale TEXT --refs UUID,...` records an attributed assessment in memory. Use visible post-report MAIN record UUIDs for `--refs`.
- `stop --url STOP_URL` ends the view and discards manual assessments. Automatic tracking remains reconstructible only while the native records remain available.
